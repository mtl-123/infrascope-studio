# InfraScope 日志系统补全方案

版本：2026-10-18。本文区分“本次交互 Demo 已实现”与“生产后端待实现”。

## 1. 日志系统的目标

运维人员应能从一条告警找到对应日志，从日志定位设备、Docker 名称组、具体实例和服务，再确认采集是否可信。日志没有错误，不等于服务正常；没有收到日志，也不等于没有事件发生。

日志中心与指标、网络流量、服务探测、事件响应共享资产 ID、服务 ID、人员 ID 和时间口径。不同信号互相提供证据，但不把时间上的相关性当作已确认根因。

## 2. 本次 Demo 的七个模块

| 模块 | 可以实际操作的功能 | 边界 |
|---|---|---|
| 检索工作台 | 按环境、业务、设备、Docker 名称组、服务、源、级别、时间筛选；关键字 / 字段查询；保存视图；时间分布；分页；脱敏 CSV 导出 | 浏览器内演示数据，不是生产搜索引擎 |
| 事件详情 | 三种时间、结构化字段、脱敏输入样本、同来源 / 实例 / 代次上下文、相同 Trace ID 的日志关联 | 未接入 Span，不能生成真实调用链 |
| 异常模式 | 按模板收拢重复日志，显示次数、设备数、首末时间，点击回查 | 确定性模板归一化；历史基线和 AI 根因仍待实现 |
| 登录审计 | Windows 登录成功 / 失败 / 特权 / 审计清除；Linux SSH / sudo；账号、来源 IP、登录方式与事件 ID | 需要源端开启相应审计；当前全部为样本 |
| 采集源 | 从已有资产和 Docker 组添加 / 编辑 / 启停；展示位置、游标类型、积压、重试、状态 | 新增后为待接入，不伪造历史数据；变更采集身份保留旧配置并创建新源 |
| 解析与脱敏 | JSON / 文本预览；时间规范、未知级别标记、常见密钥字段脱敏、异常输入校验 | 多行输入视为已合并事件；真正的流式拼接、隔离和重放在 Agent 实现 |
| 告警、质量与保留 | 日志计数规则、采集健康规则、统一告警事件、证据回查、未知状态与恢复演练、保留策略草稿、操作记录 | 不发送企业微信或邮件；不执行真实数据删除；本地操作记录不构成不可篡改审计 |

界面将事件详情放在检索工作台内，将质量与保留合并为一个页签，因此导航共七个页签。

## 3. 采集来源与边界

| 来源 | 生产接入方式 | 续传 / 识别依据 | 必须处理的失败 |
|---|---|---|---|
| Linux 系统、SSH、sudo | journald 原生接口或明确配置的文件源 | journal cursor；机器 / 启动代次 | journal 被清理、权限不足、游标失效 |
| Windows 系统、应用、安全日志 | Windows Event Log 订阅 / 查询接口 | 通道、持久化 Bookmark、记录与采集代次 | 事件覆盖、日志清除、订阅中断、通道权限 |
| Docker stdout / stderr | 支持回读的 Docker API 或已配置的日志转发 | 实例 ID、流、采集代次、持久事件序号 | 驱动不支持读取、缓存关闭、环形缓冲丢弃、实例删除 |
| 应用和数据库日志 | 显式允许的文件路径 / 原生协议 | 文件身份、代次、字节偏移 | rename / truncate / copytruncate、编码改变、磁盘满、多行截断 |
| 交换机、防火墙等网管设备 | 厂商支持的 Syslog TCP/TLS；必要时兼容 UDP | 网关生成的事件 ID；保留厂商原始序号 | UDP 无确认；即使 TLS 也不等于知道设备端总产生数 |
| NAS / PVE | 厂商只读 API 或支持的日志协议 | 稳定任务 / 事件 ID、分页游标 | API 限流、保留窗口、权限或能力不支持 |
| 打印机 / 扫描仪 | 先确认具体型号是否提供 Syslog 或审计 API | 按厂商能力建立 | SNMP 有状态指标不代表能读取完整日志 |
| 自研服务 | 结构化日志与可选 OTLP 接入 | service / resource / trace context | 接入兼容性、字段缺失、资源标签高基数 |

Docker 查询按持久分组 ID 聚合，分组范围为环境 + 业务 + 项目 + Docker 名称；保留 container ID、实例名称和宿主机。重建实例不覆盖旧日志；不同环境中的同名组不混合。

## 4. Rust Agent 与接入链路

建议的数据流：源适配器 → 有界多行合并 → 解析与脱敏 → 本地持久队列 → 批量压缩上传 → Rust 接入服务 → 持久日志存储 / 检索索引 → 查询与告警。

Go 管理端负责身份、权限、资产、配置版本、通知路由和 Web 业务接口；Rust 负责 Agent、协议接入、清洗和高吞吐查询接口。网页仍由 HTML / CSS / JavaScript 渲染，Go 不替代浏览器端交互语言。

关键约定：

1. **先保证可恢复，再推进读取位置。** 源游标与事件进入本地持久队列的状态应可共同恢复。重启后重放未确认事件。
2. **服务端持久接收后才 ACK。** ACK 表示满足约定持久性边界；检索可见水位另外报告。收到网络包不能当作完成入库。
3. **至少一次传输 + 稳定事件 ID 幂等。** ID 由 Agent / 来源 / 代次 / 持久序号或来源稳定事件 ID 组成。正文相同的两次事件不能因文本哈希相同而被删除。
4. **明确持久性边界。** ACK 的最高连续序号、重试批次、部分失败、毒性记录的隔离确认都要定义。跨存储双写须有可恢复的日志 / Outbox 或等效机制，不以两个独立成功回调冒充原子提交。
5. **有限资源。** 内存队列、磁盘队列、单条大小、并发源数、上传速率、重试间隔都有上限。达到限制时按日志类型执行已配置的阻塞、降采样或隔离政策，同时上报告警与准确计数。
6. **优先保留审计与错误。** 需要降采样时只作用于明确定义的低价值日志，携带采样率与原始计数。安全审计是否允许丢弃由公司政策决定，不能默认允许。
7. **权限最小化。** Windows 服务、Linux 用户、Docker 访问和设备凭据按适配器隔离；不要让只读采集凭据同时获得容器任意执行权限。

Rust 的内存安全和并发能力有帮助，但不能自动保证低资源占用或零丢失。性能结论必须来自指定负载与故障试验。

## 5. 统一日志记录

| 字段组 | 必须保留的内容 |
|---|---|
| 时间 | source event time、observed time、ingested time；统一 UTC 存储，界面按指定时区展示；原始时间文本 / 时区 / 精度 / 时钟质量 |
| 身份 | tenant / workspace、site、host、source、service、Docker group、container instance、source generation |
| 位置 | 事件 ID、源游标或文件偏移、来源序号、Agent ID、采集批次与解析器版本 |
| 内容 | 原始级别与统一级别、脱敏正文、结构化属性、parse status、multiline / truncation 标志 |
| 关联 | 可选 trace ID / span ID、请求 ID、服务实例、关联事件 ID |
| 审计 | actor account、source IP、login type、outcome、Windows event code / record ID 或 Linux 对应字段 |
| 权限 | 数据类别、敏感级别、归属组织、保留政策与访问范围 |

事件时间与观测时间遵循 OpenTelemetry 日志模型的区分。无可信事件时间时可用观测时间查询，但必须标记回退。原始级别无法映射时显示 UNKNOWN，不伪装为 INFO。

源事件时间到观测时间的差包含时钟偏差；它不是天然准确的单向网络延迟。负值不能截成零并混入延迟 P95。界面显示有效样本量、无时间条数和时钟异常条数。

## 6. 告警与 SRE

### 两条独立告警路径

- **业务日志告警：** 错误次数、失败比例、多条件序列、特定模式。错误比例需要明确分母与完整采集范围；仅拿 ERROR 数量不能计算业务可用率。
- **采集健康告警：** 心跳过期、积压、重试、解析隔离、磁盘队列压力、游标失效、时间异常。与业务告警分别建事件，避免断采遮蔽业务问题。

### 时间与生命周期

生产应为各源设置迟到容忍、水位和缺失区间；评估 [开始, 结束) 的已完成窗口。迟到数据修正应保留评估版本和证据，不能静默改写历史结论。断采、时钟异常、权限失败或缺少分母时状态为 UNKNOWN，已有故障不自动恢复。

Demo 采用简化演练：固定窗口计数 + 2 秒事件时间水位；心跳阈值 15 秒、水位延迟阈值 10 秒。这些是演示阈值，不是生产 SLO。历史缺口不会因收到一条新日志而消失。

事件去重键包含规则与版本、目标 / 分组、故障类别。生产应实现触发持续时间、恢复滞回、维护期、静默、抑制、通知频控与值班升级。修改规则不得改写已有事件的原始判定口径。

### 企业通知

企业微信组织同步使用稳定成员 ID，显示姓名与部门便于区分同名人；自定义人员与外部联系方式单独标记。消息包含级别、服务、设备、使用人 / 运维责任人、触发窗口、摘要及日志证据链接。

使用持久通知队列、幂等键、提供方限流、指数退避和失败升级。提供方接受、投递回执、用户确认是不同状态。Demo 中只记录模拟任务。

## 7. 查询、存储与成本

PostgreSQL 首先承载资产、人员、策略、源配置、解析版本、事件与审计元数据。小规模可用时间分区存储日志，按实测数据量决定何时拆分。不能仅凭 N 台设备决定容量；至少估算平均 / 峰值 EPS、平均事件大小、索引倍率、保留天数、压缩率和查询并发。

海量日志正文宜通过独立日志检索存储 + 对象归档隔离负载。具体产品应以代表性样本比较全文搜索、结构化聚合、写入成本和运维复杂度后选定，不在本轮假定一个产品适合所有规模。

查询服务必须强制租户 / 资产权限、时间上限、分页游标、超时、并发配额、导出行数和脱敏。高基数字段（请求 ID、正文、用户账号等）按查询需求索引，避免复制成无界指标标签。

在线检索、归档总保留、审计总保留是不同政策。冷归档必须验证可读、可校验、可恢复检索，不能只验证文件已上传。法律保全、访问撤销、备份到期与销毁任务需要明确优先级。

## 8. AIOps 的位置

先做可解释的模板归一化、频次变化、变更时间线和拓扑关联，再引入模型做摘要与排查建议。每条模型结论附日志事件 ID、时间窗、筛选条件及反向证据；没有依据时输出“待确认”。

日志是外部不可信文本。日志中的命令、链接或对模型的指令不得自动执行。只向模型发送授权范围内的脱敏上下文；根因候选和生产变更分开，人工审查 / 有限授权是执行边界。

Demo 的异常模式是固定模板算法，没有真实大模型调用，也没有自动修复。

## 9. 生产验收门槛

| 场景 | 应验收的结果 |
|---|---|
| Agent / 网关 / 接入服务崩溃 | 已确认事件按持久性契约存在；未确认事件可重放；重复不重复计数 |
| 文件轮转、截断与 Windows 清除 | 新代次可区分；游标失效可见；无法回读范围形成缺口记录 |
| Docker 重建、驱动不支持、远端缓存失效 | 实例历史不覆盖；不承诺无法实现的回读；能力状态显式显示 |
| 断网、队列满、服务端限流 | 资源有上限；策略可验证；积压、丢弃、隔离、拒收分别计数 |
| 时间乱序、迟到、漂移、无时区 | 时间质量与水位准确；不产生假正常或错误的延迟 P95 |
| 登录审计和脱敏 | 相应通道权限与事件配置生效；敏感样本不会流入查询、通知或模型 |
| 告警与恢复 | 完整窗口触发；重复评估不重复建事件；断采不恢复；新有效窗口才可恢复 |
| 资源预算 | 在指定 EPS、大小分布、并发源数下测 CPU、RSS、磁盘 IO、网络、排队与索引可见延迟 |
| 权限与归档 | 跨组织访问被服务端拒绝；导出留痕；归档恢复与到期删除可验证 |

不要以“Rust 实现”或“AI 写的代码”代替上述验收。

## 10. 已执行验证与限制

本轮自动验证覆盖查询组合与时间边界、上下文隔离、重复上报、正文相同事件保留、脱敏、解析异常、CSV 公式中和、采集缺口与时钟异常、统一告警去重、恢复与证据回查、源身份变更、新源不伪造历史，以及全部七个模块的渲染路径。

原有资产、网络、人员分组、SRE 模块的测试一并运行。浏览器预览基础设施此前无法启动，因此本轮没有宣称完成像素级截图与真实浏览器交互验收。当前页面是前端演示，Rust / Go 服务、生产存储、真实消息投递仍待实现。
