# InfraScope 使用手册

## 登录与第一台 Linux

打开平台的 HTTPS 地址，管理员向使用者提供平台账号。全新 Compose 安装的随机账号保存在服务器本机 `.runtime/admin.json`；原 WSL 开发环境在 `.local-dev/admin.json`。不要把密码发到公开 issue 或提交仓库。

左侧“使用帮助” → “逐步接入 Linux”，依次：

1. 选择已有 Linux 资产，或填写名称、物理/虚拟类型与责任人。没有联系人时管理员可同页登记。只安装 Agent 不需要 SSH 密码或远程账号授权。
2. 选择客户端是否在平台同一个 Linux/WSL。确认目标架构 x86_64、GNU glibc >=2.34，并在目标执行页面的 HTTPS 检查。远端不能使用 127.0.0.1/localhost。
3. 下载对应客户端和配置，校验 SHA256、解压，生成一次性 host 注册令牌。按提示输入令牌并运行 enroll、once、run。令牌有效期 10 分钟，注册成功后保留本机 host-state，后续不用再次注册。
4. 在“确认真实上报”选择与 hostname/status 对应的客户端，等待新鲜样本；也可打开“查看真实指标与配置”。注册成功不等于已经上报。

run 为前台运行，Ctrl+C 停止，退出终端会结束。开机自启需按客户端 deploy/DEPLOYMENT.md 为最终服务用户配置并验证。首次网卡速率为空是差分基线尚未建立。

## 常用任务

- **添加资产**：“设备与使用人” → “＋ 添加资产”，选择类别、系统、责任状态及对应联系人，保持启用；仅采集时不必勾选 SSH/SFTP/RDP，也可取消保存后继续连接。
- **生成令牌**：“Agent 策略” → 对应资产“注册客户端” → host/docker/pve。每种类型与每台机器使用独立身份和 state_dir。
- **修改采集周期**：“查看指标与 Agent” → “配置”，区分期望版本和已应用版本。
- **远程连接**：对应资产“连接 / 文件”，按提示补齐端点、远程 OS 账号、凭据及本人明确授权。管理员身份不会自动取得目标账号使用权。
- **Docker / PVE**：使用独立 Collector。Docker 需要受控 Engine API；PVE 需要可信 HTTPS 与最小权限 API token。细节见 telemetry-agent/docs/COLLECTORS.md。
- **Windows RDP**：需要本人 Windows 连接器、当前浏览器会话配对、签名与本机确认；平台主机的网络条件不能替代用户电脑到目标的网络条件。

## 排查

| 提示 | 处理 |
| --- | --- |
| 尚无有效账号授权 | 属于远程接入；安装 Agent 请去逐步接入/Agent 策略 |
| 联系人列表为空 | 管理员在同页或“组织与人员”新增启用联系人 |
| localhost 无法从远端访问 | 配置可路由 HTTPS 地址、匹配证书和必要来源网络 |
| TLS 验证失败 | 核对域名、有效期与 ca_cert，不关闭证书校验 |
| 令牌过期或被其他身份使用 | 重新生成；已成功注册则保留原状态目录直接运行 |
| 已注册但没有样本 | 查看客户端错误，运行 once/run，检查时间、资产启用与配置回执 |
| 找不到客户端下载 | 部署者需从源码构建并发布对应客户端包；服务镜像本身不自动包含 Rust 二进制 |

网页“帮助与使用手册”可按关键词搜索以上主题。当前功能边界见 docs/STATUS.md，演示页面数据不能当作生产采集结果。
