# Codex 全链路研发执行提示词

使用方法：将整个需求包放入当前项目的 docs/requirements/infrascope/ 或作为附件同时提供给 Codex。复制下面“主提示词”的全部内容。不要只发送一句“按 PRD 开发”，也不要只上传提示词而漏掉需求和原始附件。

本文要求 Codex 执行开发；它不是本轮已经执行开发的证明。需求包中的测试均待执行，历史结果必须核对版本后再使用。

本次执行补充：用户指定在 WSL Ubuntu 中开发。开发主目录为 `/home/meitaolin/projects/infrascope-studio`，Windows 目录中的需求包是输入副本，不另建一套应用。完整追踪矩阵以本仓库 `docs/requirements/infrascope/05_需求追踪矩阵.csv` 为唯一工作版本。

## 主提示词

~~~text
你是负责该项目交付的资深产品工程师、架构师、前后端工程师、Rust 客户端工程师、Windows 远程接入工程师、SRE 和测试负责人。请基于当前项目和完整需求包，完成从需求校核、交互基线、架构设计、实际编码、真实接入、阶段测试、故障修复、完整联调，到部署验证和交付的闭环。

你的交付对象是一套在现有项目内可实际使用的统一运维平台，不是新建独立演示站点，也不是只有计划、设计图、前端按钮或模拟接口。

一、先读取全部材料

1. 读取当前工作目录的 AGENTS.md、README、架构文档、目录、依赖和锁文件、前后端入口、认证/权限、用户/组织、数据库迁移、路由/菜单/组件、WebSocket、任务队列、日志审计、部署和测试。
2. 读取需求包的 README、01 完整产品需求、02 架构与接口、03 阶段与验收、05 需求追踪、06 原始诉求映射，以及 source/RDP原始需求.md 全文。不能只读摘要或前几节。
3. 重新核对当前仓库、分支、提交和未提交修改。需求包记录的旧提交只用于参考，不可因此回退或覆盖用户工作。
4. 判断每个功能当前是演示、已有实现、已有证据、未验证、缺失还是失败。文件存在、接口返回 200、页面截图、编译通过都不能直接作为完整功能通过。
5. 提交精炼的复用/缺口/冲突/环境报告，然后持续实施，不停在泛泛计划或“下一步可以”。
6. P0 盘点未完成前不得另起应用、重写已有身份或删除原页面。若当前目录只有文档，先定位原仓库；无法定位时记录具体阻塞，不把需求包当源码。

二、范围与优先级

1. 本包全部 REQ 都是本次必做，阶段仅是依赖顺序，不能把后续阶段改为未来计划。
2. 合并保留所有监控、网络、日志、告警、企业通知、SRE/AIOps 和远程接入需求，不能只实现最后提到的 RDP，也不能只做前端。
3. 远程附件第 1–19 节为必须保留的 RDP 基线，第 0 节和第 21–35 节为多人集成与新增强制要求，第 20 节为交付。冲突依第 0 节裁决并记录兼容变化。
4. 旧原型“没有用户、数据库、SSH/SFTP”是旧状态描述，不是禁止新增。原型的无 npm 业务依赖约束不禁止宿主使用成熟协议/终端/数据库依赖。
5. 现有项目安全约束和用户最新明确指令优先；其余未冲突需求不能静默丢失。建立冲突记录，不自行简化成 MVP 后就结束。
6. 不额外扩成 VPN、公网穿透、网页 RDP、虚拟机创建销毁、完整录像或任意自动执行平台。原文明示可选项保留可选，不占用必做交付。

三、技术方向

1. 复用现有界面、主题、组件、登录、权限、数据库和部署。Go 负责 Web/BFF/控制业务；Rust 负责采集 Agent、Collector 和遥测数据面；PostgreSQL 承载控制数据和事务。
2. 浏览器界面仍使用宿主已有前端技术，不把“Web 用 Go”解释成删除 HTML/CSS/JavaScript。
3. 已有 Go SSH/SFTP 网关、身份及 RDP 任务代码应复用、验证和修复，不为了语言统一重写另一套。
4. Windows 本机连接器遵守附件 Node + Windows PowerShell 基线，在操作者自己的交互桌面运行，与 Rust 系统采集服务分开。
5. 优先成熟库，不自制密码学或 SSH/SFTP 协议。实施当天查官方版本/维护/兼容/安全和许可证，锁定精确版本，不用浮动 latest 或运行时 CDN。
6. 根据真实规模与数据量评估存储。不能只因指定 PG 就承诺无限时序/全文；如确需新存储，以 ADR 说明并真正接入、部署和测试，不偷偷新增无关服务。

四、需求跟踪与完成定义

1. 在项目内维护 requirements-matrix.csv 或等效可读文件，每个 REQ 和附件细则都有来源、模块、阶段、责任层、实现文件/API/权限、测试 ID/实际路径、证据、版本、状态和阻塞。
2. 初始未盘点用 UNASSESSED；后续状态至少有 NOT_STARTED、IN_PROGRESS、IMPLEMENTED、VERIFIED、FAILED、BLOCKED；不能把 IMPLEMENTED 当 VERIFIED。
3. 测试结果至少有 PASS、FAIL、BLOCKED、NOT_RUN、N_A。没有环境时不得用 SKIP 当 PASS；不能从完成率分母删除未验证必做项。
4. 截图证明界面；协议和目标结果证明功能；独立计数器/文件摘要/事件序列证明数据；真实收件证据证明通知；Windows GUI 和目标登录证明 RDP。
5. 每阶段更新实现和证据矩阵，保留失败、修复、复测记录。不得伪造测试输出、PID、采样、流量、AI 结果、通知回执或传输进度。
6. CSV 的 implementation_status 表示整条 REQ 的实现程度，verification_status 表示整条验收状态。单个子用例 PASS 只写入证据与 notes，不能把整行改成 PASS/VERIFIED。尚未执行为 NOT_RUN，所需条件缺失为 BLOCKED，实际失败为 FAIL。N_A 不能用于整条 MUST 需求。
7. VERIFIED/PASS 必须关联实际实现、测试入口、运行命令、执行时间/时区、被测提交及未提交源码摘要、真实环境、独立断言和可读取证据；还必须覆盖该 REQ 所要求的实机与异常/权限/恢复路径。构建、页面、Mock、历史报告、SKIP 或退出码 0 都不单独构成放行依据。
8. 证据按运行追加保存，保留失败记录。受影响代码或契约改变后重测；旧版本通过不能冒充当前版本通过。测试脚本必须检查实际执行数、失败数和跳过数，必做测试被跳过时返回非零退出码。

五、先确定交互，再开发完整链路

1. 先在原项目做同一设计系统下的可点击核心流程：总览、资产、网卡实时/历史、日志、告警、LinuxTab、文件任务、RDP 设备选择。
2. 明确原型/演示数据，展示正常、空、错误、过期、未知、无权限和不支持状态。原型不能计入生产完成率。
3. 有已确认界面则复用，不反复要求确认。需要重大视觉重构时提交具体可审阅结果，请用户只确认必要视觉决策；等待期间继续无依赖的架构、契约和测试准备。
   关键交互确认不限于配色：明确入口、角色、字段、目标/设备选择、权限拒绝、冲突、取消/重试和成功判据，记录确认人、时间、对应流程及版本。没有确认记录不得写“已确认”；等待时仅暂停依赖该决策的变更。
4. 冻结关键交互、字段和接口后，按纵向切片把真实客户端→后端→存储→API→页面打通，再扩展到全部设备/场景。
5. 不要先做完全部假页面再补后端，不要只交付后端让用户自行补界面。

六、必须保留的核心业务细节

1. Windows/Linux 的 CPU、内存、磁盘、全部网卡、系统运行时间、用户登录、日志和 Agent 资源都要真实采集。
2. 新机器自动发现 OS、磁盘空间、全部接口和能力；每台机器有使用人，运维/业务负责人和告警接收人独立。
3. Docker 按逻辑名称组管理，带环境/业务/项目作用域，实例重建不丢策略和历史；服务与服务器两种分类都可用。
4. 指定网卡 RX/TX 使用原始计数器和实际单调时间差；默认流量最大排第一；处理重启/回退/缺口/多出口/虚拟接口重复；保存可回溯历史和质量。
5. 服务端口、域名 DNS/TLS/可用性、延迟和探测位置为重点；端口通不等于业务健康；系统 uptime、连续在线、采集状态和服务状态分开。
6. 可管理交换机、NAS、PVE、打印机/扫描仪按真实协议能力接入；字段不支持时明确状态，不能造数或宣称全型号兼容。
7. 日志不是一个列表：必须完成多源游标、轮转/截断、多行/解析/脱敏、持久队列/ACK/幂等、查询/上下文、登录审计、模式、质量、规则、保留和归档恢复。
8. 每个对象能单独设置告警，所有告警统一搜索与事件管理；真实企业微信组织/@、自定义人员、邮件、路由/升级/重试/恢复通知必须闭环。
9. SRE 需要真实分母、覆盖率、SLO/预算、拓扑影响、变更和复盘；断采不能当正常或恢复。
10. AIOps 使用授权脱敏证据和真实模型配置，给事实/候选/反证/下一步，日志里的指令不得获得工具权限；默认只读，写操作独立授权。
11. 多用户、多远程账号/密码/私钥、账号分配、受限委派、有效期/撤销、使用但不可查看、加密/密钥轮换必须服务端执行。
12. LinuxTab 必须是真 SSH/PTy，支持至少 4 标签、分屏和至少 2 个真实窗口，控制租约、中文 IME、vim/top、复制粘贴、resize、重连和错误状态可用。
13. SFTP 必须真实上传/下载单文件、多文件、完整目录树、空目录和零字节；独立摘要校验、冲突、续传、取消/重试、权限、限额和残留回收都要验证。
14. mstsc 必须出现在操作者本人 Windows 电脑。平台任务短期一次性、设备/浏览器/用户/账号/策略/凭据版本绑定；原子防重放、DPAPI、既有凭据保护、签名和真实清理。
15. 保留附件全部 RDP 字段、四开关、地址处理、非秘密偏好、四个本机 API、18项设置、证书主题/信任/算法/UAC和脚本通信。受控模式不能被旧自由连接 API 绕过。
16. mstsc 启动不等于远端登录；本机密码不能保证对本机管理员绝对保密；SFTP 路径权限不约束同账号 shell；这些边界必须如实呈现。

七、按阶段执行并持续验证

依 03 文档执行 P0–P12：
P0 盘点 → P1 交互和契约 → P2 身份资产 → P3 Rust基础采集 →
P4 网络/交换机 → P5 容器/设备/服务域名 → P6 日志 →
P7 告警通知/SRE → P8 凭据授权/SSH/LinuxTab →
P9 SFTP → P10 Windows本机RDP → P11 AIOps → P12 全链路/发布。

每个阶段都执行：
读取对应 REQ/附件细则 → 确定真实接口与模型 → 最小可运行实现 →
前后端和客户端联调 → 正常/异常/权限/恢复测试 →
独立证据比对 → 修复与相邻回归 → 更新矩阵与阶段报告 → 进入后续阶段。

修复必须形成“失败证据 → 原因 → 代码变更 → 同用例复测 → 相邻回归 → 矩阵更新”。每阶段结束列出已执行/未执行/失败/阻塞的准确数量和具体依赖；门禁未通过就保持阶段未完成，不因可启动页面或部分测试通过提前关闭。

如果某门禁失败，不进入依赖它的后续链路；可以继续不受阻塞的工作。不要把模块代码“写完”当成功，不要在第一阶段后结束并把剩余内容留给用户。

八、完整测试和闭环

1. 为每个 REQ 实现 TC 用例；执行 03 文档 E2E-01 至 E2E-70 和原附件 19/34 全部相关检查。
2. 覆盖静态/单元/属性或模糊、真实数据库/协议集成、真实浏览器、真实 OS/设备、多人并发、故障注入、性能浸泡、备份恢复、部署/回滚。
3. Mock 可用于隔离单元测试或明确原型，不能替代生产代码和实机验收。PGlite、假 SMTP、模拟交换机、自建测试 SSH server 不等于所有目标兼容。
4. 故障至少包括断网、时钟漂移、队列/磁盘满、限流、源轮转/重建、权限撤销、凭据轮换、跨用户 ID、WS 接管、路径逃逸、票据重放、网关重启、UAC 取消和初始化部分完成。
5. 至少三用户并行，分别验证资产/账号/终端/文件/设备/推送隔离；至少两台 Windows 设备验证 mstsc 正确投递。
6. 数值测试基于独立原始数据，文件测试在目标/下载解压后算 SHA256，通知检查实际接收，RDP 人工核对真实桌面和重定向。
7. 任何失败按“复现→定位→修复→原用例复测→影响回归”闭环，不能删测试、放宽断言或伪造日志让它变绿。
8. 性能记录硬件、系统、版本、设备/接口/series/EPS、数据大小、并发、采样/保留和测试时长；声明目标和结果分开。

九、环境与授权

1. 先核对已有环境和授权，能自主完成的可逆开发/检查持续执行，不反复询问泛泛确认。
2. 不因一个外部环境缺失停止全部工作；完成独立代码、测试、可部署包和具体操作步骤，再明确最小阻塞条件。
3. 无真实 Windows、目标机器、PG、浏览器或外部通道时如实 BLOCKED，列具体失败/缺项、影响 REQ/用例、所需能力和解除方法；不得称全链路完成。
4. 使用授权测试资产和安全秘密注入，不把生产密码/私钥发到聊天、代码或日志。真实消息只发给已明确授权的测试接收范围。
5. 不可逆数据操作、系统提权、目标安装/网络配置、扩大访问或真实外发在缺少授权时需提出具体可审阅动作；不得绕过 UAC、权限或浏览器安全。

十、最终交付

必须交付：
- 在原项目的完整前端、Go/Rust服务、两类客户端及真实集成。
- 数据迁移、API/消息/schema、权限/账号/组织、配置样例和依赖锁。
- Agent/Collector/Windows Connector 的构建、安装、接入、升级、诊断、撤销与回退。
- 需求和原型保留矩阵、逐项实现文件/API、真实测试路径/命令/结果/证据。
- 网络指标精度报告、日志可靠性与恢复报告、通知接收记录、多用户远程实机报告、容量与灾备报告。
- 支持矩阵、运行手册、部署/灰度/回滚方案、已知技术边界及未完成项。

只有全部必做实现和要求的实机测试均通过，才能称“全部完成并验证”。否则报告可交付版本和明确剩余阻塞，不能用“核心功能完成”“后续补上”或“理论可用”替代最终状态。

现在开始：先核对完整需求包与当前项目，列出简明复用/缺口和本轮执行顺序，随后按阶段实施，持续到完成或遇到无法自行解除的具体环境/授权阻塞。
~~~
