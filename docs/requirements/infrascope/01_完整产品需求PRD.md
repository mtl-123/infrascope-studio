## 3 产品边界和成功条件

服务对象：平台管理员、运维/SRE、资产与账号管理员、业务服务负责人、设备使用人、审计员。机器使用人、运维负责人、业务责任人、告警接收人可以不同，必须分别建模。平台用户、企业微信成员、远程 OS 账号、凭据、Agent 身份、本机连接器身份不能混用。

成功条件：

- 在一个入口查看设备、服务、端口、域名、容器名称组、网卡、日志和告警，能按机器或业务服务切换视角。
- 新资产接入后由实际采集发现系统、磁盘、全部接口、运行时能力，展示事实来源、采集时间、可信度。
- 每项数据能解释口径、时间、单位、采样间隔、缺失和误差；准确与及时是可测目标，不使用“绝对精准”“零延迟”承诺。
- 告警能关联影响、证据和责任人，真实投递、确认、处理、复测、恢复、复盘全过程有记录。
- 多人同时 SSH/SFTP/RDP 不串数据或账号，Windows 的 mstsc 在操作者本人电脑上启动。
- 所有必做需求有实现位置、正常/异常/权限用例和当前版本证据。BLOCKED、SKIP、NOT_RUN 都不等于 PASS。

## 4 技术方向与复用原则

Go 负责 Web 服务/BFF、身份权限、资产和配置、通知编排及已存在的远程网关；浏览器交互仍使用宿主的 HTML/CSS/JavaScript。Rust 负责 Windows/Linux 采集 Agent、边缘设备 Collector、遥测接入、处理和需要高吞吐的后台任务。PostgreSQL 是业务元数据和事务事实来源。

已有 Go SSH/SFTP 网关继续复用，不为了满足“后端 Rust”字面理解重复实现另一套身份和远程网关。若要替换必须给出成本、兼容、迁移与回退 ADR，不能擅自重写。Windows RDP 连接器继续遵守附件 Node + Windows PowerShell 基线；它与 Rust 采集服务是两种不同职责的客户端。

优先复用成熟协议库、密码学、终端和存储能力，自研业务模型、采集适配、准确性链路与体验。AI 写代码也必须通过协议、实机和资源验证。数据量未知时不能直接承诺 PG 可承载任意 N 台设备；先量化 series、EPS、保留期和查询负载，再确定物理存储，详见架构文档。

| 业务健康 | 正常、延迟、故障、未知、维护 | 服务检查/SLO，有数据覆盖门槛 |
| 采集健康 | 新鲜、延迟、断采、权限不足、不支持 | 心跳、游标、水位、队列与适配器错误 |
| 持续时间 | 系统运行、连续探测成功、故障持续、最后见到 | 各自起点独立，显示证据与时区 |

当前健康和历史有缺口可以同时成立；新收到一个样本不能消除历史断采。

## 7 默认产品参数及目标

下表为启动设计与实验基线，须经 P0/P1 容量和环境盘点校准，不是已达到的性能。变更要记录理由、影响与重新验证。

| 项目 | 初始目标/默认 | 验证要求 |
|---|---|---|
| 主机基础采样 | 5 秒 | CPU/内存/磁盘实际间隔与丢采样比例可见 |
| 重点网卡实时采样 | 1 秒，其他接口可配置为 5 秒 | 区间平均；1 秒轮询交换机须按设备负载验证，不强制所有设备 1 秒 |
| SNMP 轮询 | 10–30 秒按设备能力配置 | 超时与重试不能重叠堆积 |
| Agent 心跳 | 10 秒；30 秒无心跳进入 stale/疑似失联 | 不直接宣布关机；故障判断结合其他探测 |
| 展示及时性 | 正常链路下，从观察到前端可见 p95 ≤ 3 秒；基础指标可见间隔另含采样周期 | 分开报告采样年龄、传输延迟、索引可见延迟和刷新延迟 |
| 日志正常索引时延 | 从观察到可查询 p95 ≤ 5 秒，峰值 p99 目标另测 | 源时钟不可信时不用源事件时间估单向延迟 |
| 告警评估与发送 | 已完成窗口可见后 p95 ≤ 10 秒评估；进入待发后 p95 ≤ 10 秒开始发送 | 不包含规则持续时间或供应方投递时间，均独立计量 |
| 撤权 | 新请求即时重验；活动受控 SSH/SFTP ≤ 10 秒停止 | 网络分区失去租约时 fail closed；不套用到已建立原生 RDP |
| Agent 资源 | 参考主机仅基础采集空闲 RSS ≤ 80 MiB、单核 CPU 平均 ≤ 1% 作为初始目标 | 明确硬件、核数、采样/日志负载；峰值与磁盘队列另测，不能只给空闲数字 |
| 参考容量 | 小型 100 台/800 接口/2000 EPS；扩展 1000 台/8000 接口/20000 EPS | 两个实验档，不是用户现有规模或保证；模型/查询/远程会话并发单列 |
| 诊断与保留 | 网络 1秒数据先按 7天、1分钟90天、1小时1年评估；日志在线14天/归档90天评估 | 容量、公司政策、故障排查粒度确认后配置；降采样不承诺保留秒级峰值 |

性能不达标时必须定位、优化并复测，或明确提出可审阅的容量/架构变更；不能直接删掉必做功能来“通过”门禁。

## 8 全局完成定义

一个需求达到 VERIFIED 必须同时具有：真实实现、真实持久数据或协议结果、有效服务端权限、完整状态与错误、必要恢复路径、该版本测试和证据、操作/部署说明。实现存在但没验证是 IMPLEMENTED；被环境挡住是 BLOCKED；正在排查失败是 FAILED。

每个阶段交付可运行增量；最终验收必须覆盖全部 REQ、附件第 19/34 节和 03 文档的完整业务闭环。每次修复先重现，再修复、回归、检查相邻影响，保留失败及通过记录。生产上线后完成冒烟、观察、回滚演练或已批准的回滚验证，再关闭交付。
