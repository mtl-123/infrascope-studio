# InfraScope 分阶段开发与闭环验收

本文件是待执行的验证方案。以下用例当前均为 NOT_RUN，不是测试结果。历史项目报告只用于确定已有基础。每次实际执行必须记录被测提交、环境、输入、输出、断言和证据。

## 1 交付方法

按“需求核对 → 原项目交互基线 → 数据/接口契约 → 单条真实纵向链路 → 模块增量 → 异常和安全 → 多端联调 → 容量/恢复 → 发布验证”的顺序。避免先把所有页面做完，再发现采集端与 API 无法支撑；也避免未确认界面就全站重构。

一个纵向切片必须同时贯穿前端、API、权限、数据库、采集/连接器和实际结果。例如首条网卡链路应先完成一台真实 Linux 的计数器→接收→保存→查询→页面→历史回看，再扩展 Windows/交换机；不得把阶段 3 仅交付“Rust 项目能编译”。

阶段门禁失败只阻塞依赖它的后续工作。可以继续做不依赖故障环境的代码、契约和测试，不应因一个 Windows 测试机缺失就停止整个产品；但最终状态仍未完成。

## 3 各阶段具体工作包

### P0 项目盘点

- 读取规范、代码树、锁文件、登录/权限、PG 表/迁移、页面组件、业务任务/审计、部署和原测试；记录提交及用户未提交修改。
- 建立 CURRENT_STATE、REUSE_MAP、GAP_ANALYSIS、RISK_REGISTER、SOURCE_TRACE。逐项判断“演示/实现/已验证/未验证”，不能批量假定完成。
- 确定可用 Linux、Windows、浏览器、PG、目标网段、设备型号、SMTP/企业微信测试范围；缺少的环境记录申请对象、用途、最小权限和阻塞用例。
- 使用无秘密测试数据、专用租户/资产/目录。依赖与工具先检查已有能力，不自动重装整个环境。
- 门禁：不删除现有数据；旧用例基线可复现；需求和来源无未解释缺失。

### P1 交互与架构基线

- 在原应用实现总览、资产详情、网卡历史、日志检索、告警详情、LinuxTab、文件任务、RDP 设备选择的可点击流程，原型数据明显标识。
- 一次展示核心视觉差异和正常/空/错误/无权限状态；沿用已确认设计则无需重复审批。重大新增布局等待视觉决策时，继续协议/测试准备等独立工作。
- 固化共享组件、颜色/字体/密度/表格、导航和深链；为新 API 编写 OpenAPI、消息 schema、数据字典、权限矩阵。
- 完成数据存储、采集持久 ACK、日志水位、统一资产 ID、Go/Rust 职责、通知 Outbox、远程模式等 ADR；记录拒绝过的方案和原因。
- 门禁：最少一条端到端数据契约可运行；页面不是无法落地的静态图；容量计划明确。

### P2 身份资产

- 在现有身份之上补组织/人员、工作空间、角色/组和全部敏感动作授权；不要重新发明登录。
- 统一监控资产和远程资产引用，增加所有者、协议、分类、版本、发现来源和拓扑关系。
- 执行空库迁移、现有数据升级、重复迁移、权限角色和备份恢复预演；保护 ra_ 既有真实数据。
- 门禁：A/B/C 权限隔离、同名联系人、归档拒绝、组移除与改密失效，UI 与 API 都正确。

### P3 Agent 与主机

- Windows/Linux 都提供真实可构建运行的 Rust Agent、配置、服务生命周期及日志诊断。
- 先打通一个指标，再全量 CPU/内存/磁盘/网卡/当前登录与采集健康；区分 OS 差异和源权限。
- 测断网、ACK 丢失、进程强杀、队列满、时钟改变、配置错误/回退、升级重启；验证游标和重复处理。
- 门禁：真实 OS 计数器可独立复算，持久化后刷新仍有历史，资源数据实测。

### P4 网络交换机

- 实现接口身份、所有接口列表、IPv4/IPv6 出口候选、人工锁定、多路径、虚拟接口与去重规则。
- 同时保存 raw counter 和区间数据，做好历史桶、覆盖率、默认总流量降序和 drill-down。
- SNMP 接入至少一款授权交换机，按真实型号验证速率、错误/丢弃、端口状态与支持的硬件信息；完善能力矩阵。
- 门禁：接口/设备重启无假尖峰；断采不插值伪造秒级流量；高负载下采集开销可控。

### P5 Docker 设备服务

- Docker 逻辑组为策略/负责人主对象，实例 ID 只用于具体实例；重建后历史和告警连续。
- PVE/NAS/打印机/扫描仪分别使用获授权只读方式，不强行用通用主机 Agent 伪装能力。
- 登记端口/外部入口/域名/探测位置，验证 DNS、TLS、响应内容和延迟归因，关联服务与承载关系。
- 门禁：端口通但业务错、主机正常但域名错、容器 running 但 health fail 等都能分别表达。

### P6 日志

- 完成真实源 cursor/bookmark/file identity、轮转/截断、多行/编码/解析/脱敏、持久队列与幂等。
- 打通事件检索、上下文、登录审计、模式聚合、质量与归档；查询权限作用于所有上下文与导出。
- 做可计数日志生成器并独立核对生成、可回读、采集、ACK、索引、去重、隔离和丢失数量；对不可知的 UDP 总产生数明确标 unknown。
- 门禁：同文不同事件不误删；断采不假正常；恢复归档后可查询且权限不扩大。

### P7 告警通知与 SRE

- 将各对象单条规则统一为版本化评估和事件，不做每页独立告警存储。
- 维护/静默/抑制、阈值持续和滞回、路由/值班/升级、Outbox 和失败可见性同时交付。
- 在获授权测试群/账号和邮箱实发触发/恢复消息，验证服务方返回与实际接收，无法获得已读回执则明确未确认。
- 建立 SLI 分母、覆盖、预算、burn rate、拓扑影响、变更与容量预测，记录数据不足的未知状态。
- 门禁：异常触发→唯一事件→责任人收到→确认处理→新证据恢复→复盘完整；断采不会导致恢复通知。

### P8 SSH 与 LinuxTab

- 审阅复用已有账号/秘密/授权，验证密钥格式、轮换和跨账号边界。
- 真实 OpenSSH/PTY 的终端输入输出、尺寸、IME、全屏 TUI、断线恢复、主机信任与回放序号。
- 真实浏览器 4 标签、上下/左右分屏、拖动、弹窗/移入、控制租约与文件面板目标绑定。
- 门禁：3 人同时各 2 个 SSH + 1 文件任务；租约切换无重复输入；错误节点路由、重启和撤权准确。

### P9 SFTP

- 单、多文件、完整目录/空目录上传，下载单文件/ZIP64，任务/子项状态与已确认进度。
- 原始文件摘要来自独立工具，目标摘要从真实目标计算；下载后实际解压并对照清单。
- 断网/暂停/重选/同名内容变化/远端篡改/重放/磁盘满/权限撤销/进程重启/大文件与超多条目全部覆盖。
- 门禁：路径/符号链接/归档安全，所有权和资源配额通过；清理只作用于本任务对象。

### P10 Windows RDP

- 分开验收本机基线 1–19 与中央任务 21–35；不以一个 API 返回 200 替代整条链路。
- Windows PowerShell 5.1、真实 Windows 用户证书/信任/策略、UAC、Cred API、18 设置、rdpsign 与 mstsc 均实测。
- 两人两台电脑配对，中央可在 Linux，目标可为 Windows VM；每条 RDP 只在被选本人电脑出现。
- 保护既有凭据，测试同 TERMSRV 主机不同账号/端口并发、启动失败、UAC 取消、部分初始化、超时、残留回收。
- 门禁：人工核实真实桌面、目标和重定向；约 30 秒清理不是登录证明；其他凭据/会话未损坏。

### P11 AIOps

- 先确定授权检索与确定性关联，再配置实际可用模型，不硬编码“AI 根因”。
- 建立包含正确根因、无根因、缺数据、反证和恶意日志指令的评估集，记录模型/提示/索引版本。
- 工具仅白名单诊断，执行前显示目标/影响，必要写动作单独授权；输出不可信不能自动执行。
- 门禁：每个结论有证据，越权/注入拒绝，无模型或超时真实报不可用；基本监控不受 AI 故障拖累。

### P12 综合交付

- 在 staging 执行下面所有闭环与原功能回归，真实 PG、多 OS、多设备、多浏览器按声明支持矩阵验证。
- 测稳态、峰值、恢复追赶、24 小时初始 soak、资源增长；要求 72 小时或更长时明确时长和结果，不缩短后谎报。
- 完成故障注入、备份恢复、密钥轮换、升级/降级、功能开关、滚动部署和网络分区。
- 在用户授权边界内灰度发布，做真实冒烟、外部健康观测、告警投递和回滚条件检查。没有部署环境标 BLOCKED。
- 最终交付：可运行源代码与构建产物、完整迁移/API/部署、更新矩阵、实机证据和未通过项。不能用“主要功能完成”代替全部必做需求结论。

## 5 逐需求测试与证据规范

每个 REQ 都建立 TC-同后缀，例如 REQ-NET-04 → TC-NET-04。05 CSV 的测试 ID 是待开发和执行的验收用例标识，不是现成测试路径。Codex 必须补上真实测试函数/脚本、运行命令和证据。

每条测试按以下步骤实例化，不允许仅复制实现：

1. 给定：运行版本、真实环境/隔离环境、用户权限、资产和已知输入，建立独立期望值或外部观测方式。
2. 操作：从规定入口执行完整步骤，包含前端→API→服务/Agent/目标的路径。
3. 断言：比对返回、实际持久数据、目标状态与 UI；数值用独立原始计数器、摘要或生成序号验证。
4. 异常：适用的无数据/权限不足/超时/非法输入/重复/版本冲突/撤权/重启至少一项；重要安全功能覆盖所有相关类别。
5. 恢复：故障解除后重试/重连/回收，断言无重复、误覆盖、假恢复或串数据。
6. 证据：命令与退出码、时间、采样原值/任务 ID/摘要、脱敏日志、必要 UI 截图与实机人工核对。

| 证据等级 | 能证明 | 不能代替 |
|---|---|---|
| L0 静态/编译 | 语法、类型、构建和静态规则 | 真实连接或业务成功 |
| L1 单元/属性/模糊 | 算法、边界、状态机、解析/权限逻辑 | OS/协议/浏览器兼容 |
| L2 隔离协议集成 | 测试服务实际收发、DB/磁盘事务和失败处理 | 用户现场设备和 Windows GUI |
| L3 真实 OS/设备集成 | 指定 OS/型号/浏览器/供应方行为 | 所有型号、全部生产负载 |
| L4 业务 E2E/容量/恢复 | 指定环境从入口到结果、资源边界和恢复 | 环境外的绝对保证 |

终端截图只能证明界面；传输进度只能证明被观测字节；通知 API 返回只能证明提供方接受。最终结论以实际验证边界为准。

## 6 系统闭环测试目录

以下每一行是必须展开的系统场景，执行时附上覆盖的具体 REQ 与 TC。场景表覆盖跨模块链路；不能替代逐需求 TC。

| E2E-02 全新部署 | 空库迁移两次、首管初始化、HTTPS 登录、创建三用户 | 无默认密码，迁移幂等，真实用户/审计落库 |

## 8 最终放行规则

1. 所有必做 REQ 和附件细则实现覆盖完整，没有占位后端、硬编码成功、TODO 核心逻辑或假数据生产路径。
2. 正常、异常、权限、恢复和跨用户验证完成；要求真实环境的用例具有 L3/L4 证据。
3. 必需门禁 PASS 率为 100%，分母固定包含必做项。测试全部执行但存在失败不能称“全部通过”。
4. 新版本跑受影响自动测试、关键全链路、原功能回归；测试独立期望未被修改来迎合错误实现。
5. 无尚未处置的发布阻断缺陷；不谎报安全审计/商业签名/无限容量。
6. 生产部署、密钥配置、通知、采集和本机连接器实际可用；静态页面发布不是全平台上线。
7. 提供操作手册、部署/回退/灾备、权限、支持矩阵和已知技术边界；真实环境缺失时交付候选版本及阻塞清单，明确整体未完成。

## 9 自动化执行入口要求

结合原仓库生成实际可用命令，例如 check、test:unit、test:integration、test:e2e、test:windows、test:performance、test:recovery。名字可遵循宿主，但每个命令必须真实执行所标测试；不允许 echo PASS 或跳过后仍返回“全通过”。

CI 中 Linux/Windows 原生 runner 分工，浏览器用真实引擎，PG 使用原生服务；外部设备/通知/实机 UAC 作为有权限的人工或专用实验 runner 门禁，不把未运行的手工用例排除。

停止可选重复测试的条件是已消除具体风险且满足门禁；需求变化或修复有影响时按范围复测。不是无限重跑，也不能用“之前通过过”跳过新变更验证。
