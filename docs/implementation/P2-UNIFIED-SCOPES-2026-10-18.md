# P2 统一资产与只读范围

日期：2026-10-18，Asia/Shanghai。本轮继续原 WSL 仓库开发，交互遵守已确认基线。没有发布线上站点，P2 全阶段和完整产品仍未验收完成。

## 本轮真实增量

- “设备与使用人”导航改为统一 API 的真实资产，和远程模块同一 `ra_assets` ID、版本、权限及责任；“组织与人员”读取真实手工联系人。失败不回退到本地 demo。其余未接生产的页面继续明确演示。
- 新 `/api/v1/assets` 与原资产 API 共享处理器。类别/环境/地点/业务/责任人/资产组筛选、只读详情和 CSV 导出均先校验范围。指标未采集显示未知，未伪造 CPU 或在线状态。
- 新资产组只读范围支持明确资产、直接平台用户、平台用户组、有效期、停用及乐观版本。管理权限与只读范围分离；scope 不授予账号或远程连接能力。
- 原远程授权资产可见性收紧为明确 asset.view 且账号启用未归档；审计员显式可读操作点但必须有范围，不能连接。
- 003 迁移增量保留人员、资产、凭据、授权和审计。升级前已创建仅本地私有备份。
- 本地开发 DB pg_dump/pg_restore 使用独立无外网临时 PG 容器，逐表规范化内容摘要比对，未导出秘密到证据文件。

### 失败、修复、复测

- 轻量 DOM 行为测试复现：退出后迟到详情/导出仍出现；无关范围名称编辑导致秒/微秒丢失；低权限进入人员目录再回远程导航卡住。修复前 24 条中 16 过、8 失败。修复后 27/27 通过。失败记录见 `evidence/p2-scope-ui-failures.txt`。这是 Node/VM 测试，不冒充浏览器延迟网络实测。
- 统一身份失效入口清理缓存并抬请求版本；退出失败不假注销，需重读会话。权限拒绝保留导航，跨模式远程入口回“我的接入”；低权限不继承管理员标签。
- 未改动的资产组时间提交原 RFC3339 精度，主动改动支持秒/毫秒，避免提前授权。
- 恢复首次被后台租约写入导致的数据变化门禁拒绝：`evidence/2026-10-18T04-19-02-843Z-recovery-d23bb4/`。暂停本仓库 Web 进程（不改数据库）后复测通过：`evidence/2026-10-18T04-19-25-027Z-recovery-6f6fd0/`，schema 1/2/3 与逐表行数/摘要一致。不是生产恢复、密钥轮换或恢复后全应用验收。

## 浏览器与独立证据

真实 Chromium + WSL Go + 原生 PG 验证：管理员看到 3 条已创建的真实资产，无演示资产导入；详情匹配 ID/版本；字段式表单创建 1 资产/1 本地测试用户的只读范围；独立读者只看到该 1 资产且无编辑/账号管理，远程接入为空；管理员 API 停用范围后，同一读者会话下一查询为 0，浏览器下载 CSV 仅表头。

无权“组织与人员”仍显示准确权限提示并保留工作台，返回远程入口正常；退出回登录页。证据 `evidence/p2-unified-browser-report.json`、`evidence/p2-scoped-reader.png`、`evidence/p2-scope-revoked.txt`、`evidence/p2-revoked-export.csv`。测试用户和资产为明确本地合成记录，没有连接真实设备或发送通知。

## 仍未完成的边界

本轮不是 P2 全量通过。仍需企业组织同步/组织边界、完整批量导入与发现确认、全量关系与来源、生产权限/存储备份恢复验收。用户/用户组目录的规模化分页尚未补齐。已有 demo 服务/容器/日志/指标不因此成为真实遥测。

后续阶段依赖这些门禁；本轮没有跳到伪造 Rust 上报、设备采集或外部通知。Windows GUI/RDP、实际 SSH/SFTP 目标、硬件型号、通知收件、模型及部署/容量仍按既有具体条件保留 NOT_RUN/BLOCKED。矩阵中相关子用例有证据，但未提升任何不满足完整验收的 REQ 为 VERIFIED。
