# 服务器直接远程操作修正

日期：2026-10-18，Asia/Shanghai。用户反馈：希望添加的服务器能直接进入 Linux 终端、SFTP 文件或 Windows RDP，而不是只登记资产后找不到连接入口。

## 真实原因

本轮开始只读查询本地开发库：5 条资产、2 个端点、0 远程账号、0 有效授权、0 Windows 连接器。现有“添加资产”只是登记；原 SSH/SFTP/RDP 服务要求真实端点、目标账号、凭据和明确授权。管理员管理资产不等于自动得到所有系统账号使用权。

同时本地开发启动器强制把 `REMOTE_ALLOWED_CIDRS` 覆盖为空，导致用户即使在 shell 设置也不生效；现已尊重显式环境变量，默认空仍禁止全部目标，不自动允许任意网段。受控 Windows 连接器只接受可信 HTTPS，当前 `http://127.0.0.1:18080` 不能完成受控配对，不能用禁用 TLS 或偷偷改 standalone 绕过。

## 本轮实际改动

- 服务器列表与详情增加“连接 / 文件”，SSH、SFTP、RDP 均围绕选中资产展示账号与具体缺项。配置就绪只能表示可尝试，不称已经认证。
- 新增只读 `/api/v1/assets/{id}/remote-readiness`，复用实际可见性与协议授权。检查账号/凭据配置/授权/主机信任/网关策略/当前浏览器连接器，不拨号、不解密、不自动授权、不启动 mstsc。
- 将远程账号 JSON 编辑改为字段表单；Linux 与 Windows 默认协议不同，SFTP 和 RDP 独立。可在保存资产后继续配置连接，保存账号后继续设置凭据，目标 ID 不随切页串换。
- 管理员可显式“授权给我本人”：确认、重新验证、选择协议、限期、明确 SFTP 根目录和资源开关，事务审计及幂等。非管理员不能自授权；不会因为保存资产或管理员身份默认获得连接权。
- 连接前刷新只读预检和本人实际授权，再调用原真实 SSH/SFTP/RDP 接口；RDP 必须主动选择设备，不自动选首台在线设备。
- RDP 设备列表逐台核对同源、版本、心跳、当前浏览器绑定与完整自检/签名成功；能力未知的设备不列为可启动。

## 修复与验证边界

复核修复：未知连接器能力不能冒充ready；网关自身非回环IP预检须与真实出站禁止策略一致；前端动作必须在同一grant内满足协议、remoteAccount.use和动作；授权重试固定payload/幂等键；面板刷新期间锁定连接动作，防止重复SSH；面板关闭后刚创建未附着的本人SSH会话须尽力回收，身份更换不误删他人会话；RDP请求重试保留幂等意图。

原生PG第一轮 56 个测试事件（含子用例）通过，第二轮补网关自身IP后57通过，0skip；最终准确版本与结果见 `evidence/remote-workflow-final-checks.json`。PG里的SSH/SFTP为隔离测试目标，连接器为数据库协议夹具，不能替代真实服务器/Windows GUI验收。

最终前端4套合计95/95，包含27项服务器连接工作流，0skip。原始复测 `evidence/remote-workflow-ui-final.txt`；独立评审发现/修复记录见 `evidence/remote-workflow-review.txt`。迟到会话回收失败只报告未确认，不承诺取消点击等同远端进程已终止。

浏览器已验证服务器列表的连接入口、三协议缺项、结构化账号表单及取消无写入。开发DB复核仍0账号/授权/连接器/会话，没有替用户注入示例凭据或开启网络范围。真实服务器连接还需要用户在本地页面配置目标地址、系统账号和凭据、指定网段；RDP还需可信HTTPS与本人Windows连接器。秘密不要贴聊天。

## 使用顺序

1. 设备与使用人 → 目标服务器 → 连接 / 文件。
2. 配置真实 SSH/SFTP/RDP 端点；Linux通常SSH+SFTP，Windows RDP另需启用目标远程桌面，网页文件需Windows OpenSSH/SFTP。
3. 添加系统账号并保存密码/私钥。平台账号密码不等于目标服务器密码。
4. 管理员明确授权本人或由有权管理员分配账号；SFTP目录明确填写，不默认整机读写。
5. SSH/SFTP配置网关允许的目标CIDR并独立核实主机指纹；从服务器面板打开终端/文件。RDP在可信HTTPS平台配对本人Windows设备后明确选设备。

这次是交互与配置闭环修正，不是已经让所有登记服务器远程可达。目标未启用协议、网络不通或没有实机条件仍未完成。开发服务保持运行供用户浏览，未发布线上站点。
