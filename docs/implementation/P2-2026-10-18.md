## 实际链路

在 WSL 原仓库内实现：真实人员表单 → 现有 Cookie/CSRF/角色权限 → Go `/people` → PostgreSQL `ra_people`；真实资产表单 → 现有 ra_assets 稳定 ID → 分类/责任 → 同事务引用与历史 → 页面回读。没有创建第二套账号，没有把 demo 人员/资产自动导入可信数据。

- 人员手工登记，内部/外部联系人明确，不伪造企业微信 ID，不发送通知。管理员可管理，资产管理员只读选择且邮箱脱敏，其余角色不可读目录。
- 独立类别、环境、地点、业务字段。允许仅登记无远程端点的服务器/NAS/PVE/交换机/打印扫描设备。
- 新资产必须指定使用人或待认领负责人；运维、业务、通知、备用责任分别保存。责任人是联系人，不是授权主体。
- 既有资产升级保留 ID、凭据和授权，明确责任待补；不会自动创建联系人或分配负责人。
- 责任引用同 workspace 复合外键，显式绑定只接受启用人员，历史保存当时姓名/部门快照且不含邮箱。更新版本冲突拒绝，不出现部分历史或端点覆盖。
- 无端点操作失败明确；重新配置端点不恢复旧 host-key 信任。归档撤权不因取消归档自动恢复。
